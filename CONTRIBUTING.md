# Contributing to Productively

Thanks for looking. Issues and pull requests are both welcome.

## Getting set up

```bash
npm install
npx expo run:android      # or: npx expo start
```

You need Node 20+, a JDK 17+, and the Android SDK. `npx expo run:android` builds
the native project the first time and takes a while; after that `npx expo start`
is enough for anything that isn't native config.

To see the app with content in it, set `expo.extra.demoSeed` to `true` in
`app.json` and reinstall. That generates twelve days of sessions with real
per-task timings, so the charts and the notes agree with each other. Leave it
`false` in anything you commit.

## Before you open a PR

```bash
npm run check
```

That has to pass. It runs four gates:

| Gate | What it protects |
|---|---|
| `typecheck` | TypeScript across the app |
| `check:contrast` | Every accent, in light and dark, against the WCAG ratios the design targets |
| `check:tokens` | That colours come from the token layer rather than being hardcoded |
| `check:backup` | The export/import/merge logic, in plain Node |
| `check:analytics` | Streaks, completion rates and scheduled-day arithmetic, in plain Node |

The last two are the ones worth understanding before you change anything they
cover. `src/backup/fold.ts`, `src/backup/settings.ts` and `src/analytics.ts` are
deliberately free of React Native and Expo imports so they can be compiled
standalone and exercised in Node. That is not stylistic — a type error is
cheap, and a merge that silently drops somebody's routine is not. If you touch
the archive format or the streak arithmetic, add cases to the matching script.

## Things that will get a PR sent back

- **Hardcoded colours.** Everything comes from `src/tokens.ts` via
  `src/theme.ts`. `check:tokens` enforces it.
- **Emoji used as iconography.** The icon set is 57 hand-drawn glyphs in
  `src/icons.tsx`. Add a glyph rather than reaching for an emoji.
- **Storing a derived number.** Streaks, rates and averages are computed from
  `state.sessions` at read time. Nothing caches them onto a routine — that was
  removed on purpose, because a cached figure drifts from the record it claims
  to summarise.
- **Committing the `android/` or `ios/` folder.** Both are generated by
  `expo prebuild` and gitignored. Native changes belong in `app.json` or in a
  config plugin under `plugins/` so they survive the next prebuild.
- **Committing credentials.** `app.json` ships `REPLACE_WITH_*` OAuth
  placeholders on purpose. Signing keys live in `~/.gradle/gradle.properties`,
  never in the repo.

Add an entry under `[Unreleased]` for anything a user would notice.

## A note on the design

The app was built against a fixed screen board — 42 screens across 9 flows.
`docs/v2-audit.md` is the screen-by-screen diff between that board and this
code. If something looks like an odd choice, check there first; several of them
are deliberate departures with the reasoning written down.

The failure this codebase is most prone to is a screen that matches the picture
and does nothing when tapped — a whole release of those shipped once, and every
one passed typecheck. Run what you changed.
